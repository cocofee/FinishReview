## 实现与边界

- `event_ingestion.py`：接收已持久化通知，一个串行线程处理赛事投影。输入队列及提交
  通知各最多 256 项；溢出/失败从收件日志恢复。普通队列保留顺序，恢复合并最高
  revision，包括撤回 tombstone；中间审计版本保留在收件日志，不宣称恢复补写每个版本。
- `PassageEventStore`、`RaceMetadataStore`：读锁与写盘锁分离，fsync 完成后才发布内存
  状态。读操作不再等慢写盘。新增单调时钟只用于进程内度量，不进入 JSONL 协议。
- UI 提交回调先增量更新名单，再触发现有证据队列。录像准备不计入名单延迟。
  RaceTiger / 同一日志路径不重复追加。退出时通知邮箱可以淘汰旧 UI 通知，写盘仍排空，
  不依赖 Qt 继续消费通知才能退出；磁盘持续失败时收件日志用于重启恢复。
- `session_context.py`：赛事服务引用与不可变加载快照分别保存。准备、日志加载、
  revision 合并、metadata 写盘进入后台。打开历史赛事也补齐收件日志里的撤回。
- `session_controller.py`：单线程准备与生命周期任务，显式 transition 防重入，管理
  generation、事件排空、证据 FIFO 屏障及关闭。沿用 receiver/recording/evidence 控制器。
  切换前先封住旧投影写入器，避免同一 JSONL 同时存在两个写入所有者；后台准备完成后
  排空旧证据、激活上下文并重放准备期间的收件记录。
- 目标准备失败保留旧服务；接收器或录像进程停止失败时保留引用，不激活新赛事。
  录像已停止后的失败不虚报录像恢复。旧赛事提交、扫描和原帧结果沿用各自 generation
  及播放器取消机制；切换清除旧选择和回放窗口。
  额外覆盖“写盘已提交、Qt 通知尚未投递”时切换失败：根据未呈现 revision 补齐旧名单，
  避免重绑投影器后把该记录误认为已经显示。修复前测试稳定失败，修复后通过。
- 显式切换仍提供同步返回值，内部使用 Future + Qt 事件循环等待，期间禁用冲突操作，
  保持绘制、定时器和信号分发；它不是可同时执行多个用户切换操作的模式。
- 回归暴露的回放退出问题已修复：关闭后的延迟错误不弹窗，重复关闭不再访问已删除
  worker。保留单击换身份/原帧、双击定位、胶卷观察、机位 1 暂停高清及人工确认规则。
- README 胶卷时钟改为录像北京时间。未进入判读状态拆分、表格模型迁移、硬解或双机位专项。
