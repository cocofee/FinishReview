## 步骤1：独立芯片自检

### 实现

- 新增 `realtime/live_chip_checks.py`：只读赛事日志，按赛事/赛段重建有效记录，复用已有芯片规则。
  活跃记录采用最新时间、圈次和分组；重复投递不增加有效通过数，历史身份仍供已作废发现追溯。
- `ProblemListPanel.live_tick` 在视频条件判断前触发芯片检查，400 ms合并启动；独立低优先级
  `QProcess` 执行，不在接收线程或界面线程遍历完整日志。暂停视频和打开集团不阻塞芯片检查。
- 子进程仅回传JSON；界面验证赛事和生成代次后，原子发布 `finish_problems/live_chip_checks.json`。
  视频进程继续独占 `problem_list.json`，两者不竞争同一个文件。界面合并结果，保留草稿与当前问题。
- 监听芯片日志、删除标记、赛事范围、元信息变更；失败保留上一版并延迟重试。退出取消定时器并回收进程；
  重启输入签名相同不重复运行，切赛事丢弃旧代次结果。
- 状态栏独立显示芯片结果和视频等待原因；缺少名单、枪时、距离和退赛状态在状态提示中显示。
  显示“已落盘消息/有效通过”，原始读卡数和未经视频分析的候选数保留未知，不填0。
- 修复旧面板将“当前快照缺少目标记录”当作上游删除的问题：只有明确失效记录才证明上游作废。
  此修改不宣称已有完整删除同步能力。

  正常保留的短段按各自版本分析；只有跨边界合并档案而无短段时，仍需后续分段解码能力，不能宣称已核清。
- 快速调度签名检查配置和模型文件大小/修改时间；实际分析使用模型内容哈希验证缓存。
  人为同时保留文件大小和修改时间替换模型时，需要手动触发分析才能发现内容变更。
- 未重跑三场整场录像，未做第四场盲测、长时间持续录像负载对照、操作员减负计时或打包部署验证。
  这次只接通配置和证据链，不修改步骤3多芯片聚合或步骤5紧跟漏读规则。
