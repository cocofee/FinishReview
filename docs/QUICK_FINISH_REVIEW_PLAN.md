# 终点快速判读实施方案

## 目标与操作流程

界面只有一张到达表和一块录像画面。每行同时显示顺序、时间、号码和状态。
去掉“疑似自行车”“疑似行人”、模型置信度、重复的号码名单与右侧处理栏。
已有号码来自本场芯片记录，操作员不用输入号码。

1. 选择一处候选，查看录像。
2. 按 **1** 确认该处有自行车，仅改变判读阶段，不增加人数、不确认号码。
3. 逐帧找到前轮压终点线的画面，认出 321 就单击 **321 所在行**。
4. 当场保存该芯片事件、号码、录像文件、机位、帧号、片内时间、录像时刻与校时版本。
5. 继续看下一位，认出 258 就点 258。点击不会自动跳走正在看的画面。
6. 已确认行仍留在同一表内。再次点击只回看保存原帧，不重复增加人数。

**2** 表示人工确认当前画面候选为非选手；**3** 暂放当前候选并进入下一处。
**← / →** 逐帧；**↑ / ↓** 切换候选；**Backspace / Ctrl+Z** 撤销上一操作。
人数不由按键次数或芯片条数决定，也不因人数与芯片数相等而自动结束。

## 布局

- 左侧到达表：顺序 / 时间 / 号码 / 状态；未确认时间标“参考”，确认后采用实际画面时间。
- 右侧：简短的 1 / 2 / 3 工具条、已有过线时间带、完整原帧和原有播放控制。
- 模型仅在后台提供候选，不输出识别类别文字、不自动排除候选。
- 模型、分析、导出、旧异常处理等入口收进“更多”。不删除已有审核和交接能力。
- 不同时显示旧问题表、集团人数表、独立号码名单和单独过线记录列表。

## 记录来源与排序

- 将问题条目、集团/批次成员及本场有效芯片事件合成一张表；同一 eventId 只出现一行。
- 同一个号码在不同圈、不同事件可以分别确认，不按号码本身去重。
- 无芯片的画面候选显示“—”，保留待匹配，不凭相邻芯片自动认号。
- 按校时后的实际过线时间排序；未判读者用芯片时间或候选时间作参考。
- 回看补认早到选手时插回正确时间位置。排序不能因后台刷新丢失选中身份。
- 画面时间相同的已确认选手标注“同时”，不虚构先后。

## 持久化与状态

新增独立的本地 `finish_problems/arrival_reviews.jsonl` 审核日志，记录类别确认、
选手确认、非选手、暂放和撤销。通过项目已有的文件锁、flush/fsync 与追加回滚工具写入。
这些是人工画面审核记录，不修改 CycleRace 的正式时间和成绩。

- 选手确认绑定 raceId、stageId、eventId、号码、官方芯片时间和修订信息。
- 类别确认绑定候选帧、分析签名和校时版本。换候选不能继承上一处的确认。
- 官方事件改号、改时、撤销，或证据配置变化后，旧决定显示待复核，不继续算有效确认。
- 保存失败不显示成功；无原帧、无可靠录像时刻、事件不明确时不允许生成确认记录。
- 确认使用点击瞬间正在显示的原帧，不能使用候选最初截图冒充当前画面。
- 撤销追加反向记录，保留审计依据；支持重启恢复和切换赛事隔离。
- 排除只影响当前视频候选，不直接删除芯片或整批正式记录。

## 实现拆分

1. `arrival_review.py`：事件身份绑定、持久化日志、去重、撤销与有效状态查询。
2. `quick_review_panel.py`：复用已有分析、录像定位、批次数据和导出入口，替换可见布局与日常交互。
3. `review_window.py`：启用新面板，提供当前原帧，关闭默认点人数模式，将按键交给新判读流程。
4. `problem_rules.py`：模型认为是行人/其它车辆的候选仍保留供人工确认；兼容读取旧自动排除条目。
5. HTML 原型同步去掉所有识别类别描述，作为最终布局的对照。

## 验收

- 连续按五次 1，确认人数仍为 0。
- 按 1 后，在当前压线帧点 321，人数为 1；在另一帧点 258，人数为 2。
- 再点已确认的 321，只回看原帧，人数仍为 2。
- 同号不同事件分别保留；改号、改时、取消事件后旧确认失效。
- 后补早到选手按时间插入；同帧选手保留同时关系。
- 2 / 3 不确认任何选手，不删除官方芯片记录；模型不会代替操作员排除。
- 重启保留审核；撤销、磁盘写失败、工作目录/赛事切换、配置过期均有覆盖。
- 相关现有分析、问题清单、原帧定位、导出和主窗口测试通过。
