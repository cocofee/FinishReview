## 每条的处理步骤

1. 在清单里点一条：右边显示卡片（压线时刻）和小胶片（前后各约 1 秒，每 0.25 秒一张）。
2. 需要看清号码时点“跳到原帧”：主画面定位到原录像的这一帧，用原来的逐帧、放大、标线功能核对。
3. 点处理按钮。需要号码的（认号补录、删除多余芯片、建议改号改圈）先在号码框里填号码；删除多余芯片、建议删除芯片必须在原因框写原因，其他处理的原因可写可不写。
4. 如果同一帧已经确认过别的号码，系统会先提示，确认后才记录（防止定边 029 / 051 那样确认错人）。
5. 处理过的条目从待处理里移走，可以勾“显示已处理和已排除”后找到它，点“重新处理”。
6. 全部处理完后点“导出清单”，会在 `ws_dingbian\finish_problems\exports\` 生成三个文件：
   - `补录清单.csv`：号码、芯片域时间、证据帧、机位、校时版本、说明；
   - `建议删除清单.csv`；
   - `建议改号改圈清单.csv`。

   这三个文件只是给 CycleRace 的建议，FinishReview 不会改正式成绩。CycleRace 改完后，FinishReview 收到修订就会关闭对应条目。

## 计时和记录

### 集团的实际操作（0.25.1 起）

1. 选择一条集团或拥挤时段，点清单上方“打开集团逐帧核对”，或双击该条目。
2. 上方过线图覆盖整团；红色刻度是各芯片的预期过线时刻，绿色是人工计数，点击可跳转。
3. 用“上一帧 / 下一帧”或左右方向键查看原录像。在前轮压线时点一下前轮，每人只计一次；
   并排两人分别点各自前轮。右键撤销同一帧附近的误点，也可在右表选中后点“删除误点计数”。
4. 滚轮放大、拖动看号码，双击还原视野。选择右表中的计数，输入看清的号码再点“记号码”；
   双击一条计数可以回到其原帧。没有看清就留空，不能把最近芯片当成号码。
   从 0.25.2 起，确认是行人、工作人员或无关人员时，在右侧选择原因后点“确认非选手并排除”。
   灰色记录保留原因及原帧，不计入选手人数或补录；误判可点“恢复为选手计数”。
   看不清号码的选手不能作为无关人员排除；排除不会作废芯片，芯片仍未对应时保留待查。
5. 每帧显示附近 ±200 ms 的芯片；同号优先对照，其余“顺序参考”不证明身份。
   两个芯片相隔 150 ms 以内必须看号码或按名单排除。前轮和刻度的偏差优先由至少 3 位
   独立过线者估计；不足时使用窗口中的人工参考值，默认 0 ms。后方机位原型的 120 ms
   只作参考，不直接套到其他机位。
6. “保存进度，稍后继续”保留计数、号码和累计用时，不会关闭待处理问题；返回时也会保存修改。
   重新打开可继续。机位间的草稿分别保留，最终只采用最近一次确认的核对结果。
7. 看完整团后勾选“已看完整团”。只有芯片都有对应计数，多出者已认号且有前后参考可估时，
   才能点“确认本团已核对”。多出者的每个号码、各自证据帧和插值估算时间进入补录建议。
   缺少前后参考、未看清号码或有芯片未对应时，保存进度并继续保留待处理。

集团核对日志位于 `finish_problems/bunch_reviews.jsonl`，不会覆盖原有处理日志。
芯片、校时版本或证据变化后，旧结果不会继续导出。原“已核对 / 认号补录”两个集团快捷按钮
已由完整核对窗口替代，避免只看一张卡片就误标整团完成。
