# 终点现场操作流程：先确认过线，再核对芯片

日期：2026-10-16。状态：本文描述的流程已在本机实现并通过自动测试；真实比赛的计时验证与持续负载尚未进行。

## 目标

操作员先开始录像（不必等芯片到达），再画实际终点线，随后确认一位有芯片、身份明确的选手建立初始校时。
之后的工作围绕一张竖表展开：它按画面里的实际过线时间排列本场的过线记录，
单人、多人、集团、漏读、一人双芯片都在同一张表里选择，点一行就回到那条过线的原帧。

正式成绩始终采用 CycleRace 各自的芯片时间。视频只作过线证据和漏读补录的来源，不改实际成绩。
不做 OCR、不做号码识别、不依赖大模型服务；本机 YOLOX 只用于认车、行人和常见机动车，限制单线程，
与 CycleRace 和录像接收共用这台机器。

## 操作流程

### 1. 赛前准备：不必等芯片，先开始录像

- 打开时状态行写清是现场还是历史：「普通录像: 待机 / 录制中」是现场，「历史查看」是在看旧比赛；主按钮随之为开始录像、停止录像或返回现场。
- 「开始录像」不依赖计时设备先发芯片或名单：设备空闲、还没有任何通过记录时也能先保存本次摄像头录像。胶卷范围随之切到「本次录像」，昨天的画面不会冒充今天的现场，旧录像仍保留、可手动切到「全部录像」查看。
- 正在看历史赛事时，先点「返回现场」再开始录像。返回现场在没有任何新芯片信息时同样可用：优先接回独立收件箱里已收到的赛事，其次是当前已选的赛事；两处都没有时，在保存根目录下新建一个隔离的「现场录像_时间戳」目录，不会写进无关的历史赛事。
- 历史查看期间收到的实时数据只进独立收件箱，不打断正在看的历史画面。
- 赛前试芯片、试画面留下的数据一键清掉：问题清单表头的「清空数据」删除本场的通过记录、问题判读、校时和试录画面，直接删除，不保留副本、不能恢复；终点线、认车模型、摄像头和保存位置设置保留，CycleRace 正式成绩不受影响。正在录像或正在看历史赛事时该按钮不可用。
- 终点线与认车模型都在问题清单的「终点线 / 模型」里配置并试运行；设备设置中不提供这一项，那里的红黄蓝线只用于旧的运动检测区域。

### 2. 赛前画终点线

- 在本场、本机位的实际画面上画终点线，标出选手正常通过的方向。
- 相机位置变化或录制会话发生时间跳变时重新检查，不把旧校时无条件套到新画面。

### 3. 确认首人，建立校时

- 首位选手到达后，打开其压线原帧，点「以当前帧校时」，选择这位选手的有效芯片记录。
- 只提供本场有效、非补录、非测试/备用、读数未被修改的记录；保存机位、会话、原帧与偏移，后台配对立即可用。
- 第一名没有芯片、身份不明或处于遮挡中：先保存过线事实，改用下一位能明确对应的选手校时。
- 一个点只能确定此刻的固定偏移；后续用可靠的独立过线继续检查，出现冲突提示核对，不悄悄覆盖人工锚点。
- 正式芯片时间不改。重新配对时已点过的原帧与标记保留，只调整对应的关系。

### 4. 左侧一张竖表：按实际过线时间选

- 表按画面里的实际过线时间排序，一行就是一次过线；点行即在画面里打开它的原帧。
- 单人、多人、集团、漏读、一人双芯片都在这张表里选择；同一集团的相关证据归在一条主项里。
- 自动对应的正常单人只在「全部」里出现，作为本场完整过线记录供复查，不占待处理。
- 过线时间用该条证据自己的校时版本与录制会话来换算。某条证据带的版本查不到时按录像原时刻显示，
  不用更新的校时版本顶替；只有本身没有版本标记的旧证据才沿用当前生效的一版。
- 时间来自预期位置或仅有芯片时，行上标「参考」，不当作已观察到的过线。
- 表上方用「待处理 / 待证据 / 已处理 / 全部」和四个类页签（一人双芯片、集团、漏读、待确认）收窄同一张表。

### 5. 点人计数

- 画面里每位压线的人点一次，标记连同当时的那一帧一起保存；补点一位较早的人只改变表里的显示先后，
  不改动已保存标记的索引。
- 记录在同一过线时刻的几人共用同一个顺序号并标「同时」；标为「排除」的人不占选手序号。
- 点错按退格撤销最后点的那个人；也可选中一人，按「删除误点」。
- 号码不必逐人填写。需要认号时在名单里点一位，再按「记号码」；同一号码已被记在另一人身上时先提示核对。

### 6. F：原地放大，右侧还是同一张表

- 按 F 画面在原处放大，清单让开位置；右侧那一栏换成这次过线的统一表：
  顺序、过线时间、号码、芯片时间都在同一行里，不用在两张表之间来回对。
- 大画面上方保留整团的原始过线图片带、芯片刻度和检测候选分布：蓝线是画面检测到的过线
  （浅色表示当时画面被遮挡）、红线是芯片预期时刻、绿线是点出的人、灰线是已排除的人；点刻度回到那一刻的原帧。
- 只有芯片、还没在画面里确认对应的人时，那一行显示「待看」，不编排过线名次；
  按时间暂时对上的号码只作参考，不认定身份。
- 在 F 里点人、撤销、记号码、按数字键处理都与清单里一样；F 或 Esc 收回。

### 7. 集团：人数对上就完成

- 集团在同一判读布局里核对，不需要额外的窗口。点满人数、或把误排除的人恢复为选手，
  人数等于芯片条数的那一刻自动完成并保存，不需要再按一次确认。
- 不因临时的逐人先后顺序对不上而卡住：人数就是判据，逐人时间对应只用于复查和补录。
- 「回到团首」回到本团录像的起始位置，保留首人过线前的少量画面；先前的点数与已看范围都保留。
- 原有的两条校验仍在，也不扩大：本团录像存在真实缺口时不能按「完整核对」收尾；同一号码被填在多人上时先要求核对。
  除这两条外，集团完成不再设别的门槛。

## 异常怎样处理

| 看到的情况 | 表里先给什么 | 最短动作 | 保存结果 |
| --- | --- | --- | --- |
| 一个人，对应两条不同号码的有效记录 | 同一画面、两条芯片信息 | 点 1 人：选择保留和建议作废的记录 | 过线证据与精确成员建议；等待 CycleRace 更正 |
| 两个人，两条记录 | 两人的过线画面与芯片 | 点 2 人 | 正常并排 |
| 视频有选手，芯片没有 | 该人的原帧与「暂无对应芯片」 | 点人先记；号码读到就补录，读不到先待认号 | 未认号者保留，不因看不清号码被排除 |
| 有芯片，视频暂时没有 | 芯片那一行「待看」与等待状态 | 等证据到齐；仍有疑问再人工核对 | 不因暂时缺画面就建议作废 |
| 行人、工作车辆、回头骑手或其他物体 | 可用原帧与模型建议 | 点「不是选手」 | 记排除依据，不算完赛人数，不占序号 |
| 遮挡、人数或对象看不清 | 短片、其他机位或待核记录 | 「待确认」先放着 | 已做的工作自动保存，未核清部分仍可见 |

两块物理芯片不必然意味着两条错误成绩；合法双芯片绑定和上游已合并的记录不能当作一人多成绩删除。
迟到芯片到达时重新核对已有视频候选，避免重复补录。所有补录、作废或改号建议沿用现有交接链导出给 CycleRace，
不自动改写 CycleRace 成绩。

## 界面与数据口径

- 不是所有类型都自动按时间合并：只有集团上下文里的画面人与芯片会按时间作临时的参考对应；
  其余类型要由人工记下号码确认后才合并，界面与文档都不声称身份已自动匹配。
- 视频只作证据与漏读补录来源；官方成绩始终是各自 CycleRace 芯片时间。
- 等待与完成的状态分开表达：未分析、等待录像或校时、分析到某时刻且当前无待处理，不互相冒充。
- 系统没有生成候选时，仍可从原录像点人、用「＋ 补记过线」新建一条带原帧的过线记录，不要求先有问题条目。

## 本地实现状态（2026-10-16）

1. 首人校时已接通后台配对：锚点保存会话、原帧与偏移，记录后来被修改或作废时锚点被剔除并提示重新核对，正式芯片时间不改。
2. 点人计数在普通画面与 F 放大画面都能用；每个标记绑定当时原帧，切机位有防重复计数保护；一次点出的多人各自独立保存。
3. 集团以人数为判据自动收尾；板块、点数与已看范围写入集团记录，重开时恢复，不重新开始。
4. 过线时间、同时序号、排除不占位、待看不排名次等展示规则由本表的排序与名单模块统一提供，清单与集团判读共用一套口径。
5. 模型边界不变：线取样过线检测加 YOLOX 认车，减少正常单人与明显非选手的人工负担；
   这不是对任意物体的可靠识别，并排、遮挡、推车回头、低机位密集团及前后轮碎片仍需人工判断。
6. 现场入口与历史查看分开：开始录像不依赖芯片先到；「返回现场」在设备空闲、收件箱为空时也能回到已选赛事的现场待机，必要时落到隔离的现场目录；
   「清空数据」在录像停止时清掉本场通过记录、判读、校时与试录画面，保留终点线、模型与摄像头设置，并同时清掉根目录收件箱里的对应读数。

## 尚未验证

- 真实比赛计时验证：用真实赛事的记录（正常单人、正常并排、一人双芯片、漏读，
  以及「人数相等但存在双芯片与漏读」的情形）核对实际操作数、用时、残留疑点与分析积压。
  自动测试通过不等于现场已成熟。
- 没有操作员工时与全场持续负载实测；密集团加大量检测候选时的界面流畅度也尚未实测。
- 现场准备流程（设备空闲时返回现场、清空赛前测试数据）尚未在真实赛前操作中演练。
