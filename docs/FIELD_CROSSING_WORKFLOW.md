# 终点现场操作流程：先确认过线，再核对芯片

日期：2026-10-16。状态：本文描述的流程已按下面“已实施”条目落地，尚未经过真实比赛计时验证。
代码核对基线：本地 main 的 c86dbae，当前工作区已快进至该版本并完成实现。

## 目标

操作员先画实际终点线，再确认一位有芯片、身份明确的选手建立初始校时。
之后正常单人由系统自动对应；小集团直接确认人数；多芯片、漏芯片及模型无法判断的过线交给人处理。
围绕同一次过线展示证据、人数和芯片，减少在胶卷、清单、集团工具之间切换。

正式成绩继续采用 CycleRace 芯片时间。视频确认的是过线事实及其证据；漏读的补录时间单独注明来源。
不做 OCR，不依赖大模型。保留本地 YOLOX，限制推理线程，保护 CycleRace 和录像接收。

## 操作员的四步流程

### 1. 赛前画终点线

- 在本场、本机位的实际画面上画终点线，标出选手正常通过的方向。
- 明确显示“终点线已设置，等待首人校时”，录像和芯片接收继续工作。
- 相机位置变化或录制会话发生时间跳变时重新检查，不把旧校时无条件套到新画面。

### 2. 确认首人，开始工作

- 首位选手到达后，打开其前轮压线的画面，与这位选手的有效芯片记录核对。
- 点“以此人校时”，保存机位、会话、原帧、芯片记录及初始偏移；后台配对立即可以使用它。
- 如果第一名没有芯片、身份不明或处于遮挡中，先保存过线事实，改用下一位能明确对应的选手校时。
- 第一位只能确定此刻的固定偏移，不能从一个点算出整场漂移。后续用可靠的独立过线持续检查，
  有足够且跨越一定时间的支持后再拟合漂移；出现冲突时提示核对，不悄悄覆盖人工锚点。
- 正式芯片时间不改。调整的是视频与芯片的对应关系；已点过的原帧与标记保留，
  重新配对时只将受影响的对应关系标为待核，不要求操作员重新做全部正常记录。

### 3. 小集团来了，直接点清人数

- 一团作为一件事展示，打开就有该团原画面、完整过线时段和附近芯片。
- 普通画面和 F 放大画面都能点人：在该人的过线帧点一次，立即记一个人并自动保存；
  同一人在后续帧不重复点，点错可撤销。标记绑定原帧，不跟着后续画面移动到另一人身上。
- 如果整团在短片中清楚可数，可以直接输入人数或确认建议的 N 人；保存为整团人数证据，
  不伪造 N 个逐人过线标记。需要查漏读者或各人的过线时间时再逐人点选。
- 看完整团后，回车确认本次点数，继续下一条；无需逐人填写号码。
- 界面分开显示“已确认 N 人”和“M 条有效通过记录”。记录数不能当作人数。
- 人数一致且没有未解决的对应冲突，才可完成核对；人数一致本身不能排除“一个人双芯片、另一个人漏读”相互抵消。
  数量、身份或证据仍有冲突时，保留已完成的点数，只留下冲突部分待核。
- 每个物理过线的人只数一次；切机位是检查同一批人的证据，不能叠加两机位人数。

### 4. 正常单人自动处理

- 视频有独立、清晰的一次过线，芯片一对一对应，校时有效，附近没有未解释的额外过线，
  且无遮挡、缺帧等冲突时，系统自动记为已对应，不要求操作员再按确认。
- 自动对应记录可从通过记录中打开原帧复查，但不占人工待处理队列。
- 模型不确定的单人不强行通过，直接把可用画面交给操作员；一次点击即可保存过线事实。

## 异常怎样处理

| 看到的情况 | 系统先给什么 | 操作员最短动作 | 保存结果 |
| --- | --- | --- | --- |
| 一个人，对应两条不同号码的有效记录 | 同一画面、两条芯片信息 | 点 1 人，选保留和建议作废的记录 | 过线证据与精确成员建议；等待 CycleRace 更正 |
| 两个人，两条记录 | 两人的过线画面与附近芯片 | 确认 2 人；有身份冲突时再核对 | 正常并排，或仅保留尚未核清的对应 |
| 视频有选手，芯片没有 | 该人的原帧与“暂无对应芯片” | 点人先记；号码能读到就补录，不能读到先待认号 | 未认号者仍保留，不因看不清号码被排除 |
| 有芯片，视频暂时没有 | 芯片记录、录像覆盖与等待状态 | 等证据到齐；仍有疑问再人工核对 | 不能因暂时缺画面就建议作废 |
| 行人、工作车辆、回头骑手或其他物体 | 可用原帧、模型建议分类 | 点“非比赛选手 / 回头 / 其他” | 保存排除依据与证据，不算完赛人数 |
| 遮挡、人数或对象看不清 | 短片、其他机位或待核卡片 | 先记已确认部分，余下标待确认 | 已做的工作自动保存，未核清部分仍可见 |

两块物理芯片不必然意味着两条错误成绩；合法双芯片绑定和上游已合并的记录不能当作一人多成绩删除。
迟到芯片到达时重新核对已有视频候选，避免重复补录。候选等待数据到齐期间仍可先由人确认过线。
所有补录、作废或改号建议沿用现有交接链，不自动改写 CycleRace 成绩。

## 界面应该怎样呈现

- 左侧：按过线时间排列的待处理事件。同一集团内相关疑点合为一个主项，可见剩余未核清部分。
- 中间：当前事件的大画面或短片，默认就能点数；确认后留在同一判读布局，继续下一件。
- 画面下方：人数、有效记录数，以及当前需要的少量动作；只有涉及补录或具体记录更正时才展开号码操作。
- 底部主要呈现一人或一团一张的过线卡片，卡片打开对应原帧/短片。同一个人不以多张 500 ms 缩略图重复占据主工作流。
  原始时间胶卷保留为查找、校时和模型漏检时的入口。
- F 在各个判读入口统一放大当前证据，放大后继续点数、确认和切换疑点；F/Esc 收回。
  点数不以先按 F 为前提。文本输入框保留正常字母输入。
- 当前没有疑点时，中间展示最近过线或清晰的等待状态；不要对空清单显示“此问题暂无原帧”。
- “尚未分析”“分析到某时刻、当前无待处理”“已处理完某时刻之前的疑点”分开表达。
  不能在等待录像或校时的时候仅显示“疑点已清空”，使操作员误以为系统已检查整场。
- 系统没有生成候选时，操作员仍能从原录像点人，新建一个带原帧的过线记录；不要求先有问题条目，
  不要求先写一段原因。尚未校时时先保存视频时间，校时后再核对芯片。

## 已实施（2026-10-16）

1. **首人校时接通后台配对。**
   界面“以当前帧校时”只提供本场有效、非补录、非测试/备用、且记录未变化的芯片；
   保存所选记录的原始时间、修订号、赛事与原帧（`passage_evidence.py` 的锚点溯源字段）。
   后台 `problem_analysis.py` 在自动校时不可用时直接用人工锚点启动，只配对已锚定的录像会话；
   记录后来被修改或作废时该锚点被剔除并提示重新核对，正式芯片时间不改。
   `ClockModel.same_fit` 现在区分来源和会话集合，自动与人工数值相同也不会互相顶替。

2. **普通画面点人、F 统一放大、人工过线独立保存。**
   点击计数不再要求先按 F，也不再要求已有疑点：普通机位画面即可计数；
   没有对应疑点时点击会新建一条带原帧的人工过线记录（可选保留画面缩略图），不伪造芯片时间。
   每个标记绑定当时显示的原帧，翻帧后不会跑到别人身上；切机位有防重复计数保护。
   同一画面点出多人时，保存为各自独立的待认号记录，认掉一个不会把其余人一起结清。

3. **集团操作与过线卡片。**
   集团在清单内直接点人计数，完成后需真看过整段录像且人数一致；
   集团内未核清的双芯片/漏读等子疑点显示在同一工作面（选择→查看原帧→按依据处理），
   人数相等不能代替核对。成员级“确认有效/建议删除”沿用 `BatchDecisionStore` 精确绑定。
   “回到团首”按实际时间定位录像。
   正常单人自动对应后也生成过线卡片，可打开原帧复查且不进入人工队列；
   打开过的卡片用内存缩略图，不在界面里同步解码视频。

4. **等待与完成状态分开表达。**
   未分析、等待录像或校时、分析到某时刻且无待处理分别显示，不再在未检查完整场时显示“疑点已清空”。

5. **模型边界不变。**
   线取样过线检测加 YOLOX 认车/行人/常见机动车检查，能减少正常单人及明显非选手的人工负担；
   这不是对任意物体的可靠识别，也不能保证密集团中每位骑手都被发现。
   并排、遮挡、推车回头、低机位密集团及前后轮碎片仍需要人工判断。
   非选手分类不应把拥挤遮挡时段里的潜在骑手一并消掉。

## 尚未完成 / 未验证

- 真实比赛计时验证：用定边 020/023、371/376、307，同心 642，贺兰山集团 319/550 及一组正常单人、
  正常并排、“人数相等但存在双芯片与漏读”的情形核对，记录实际操作数、用时、残留疑点与分析积压。
  自动测试通过不等于现场已成熟。
- 正常单人卡片的缩略图只有打开过的才有；未打开过的先以文字卡片呈现。
- 集团子疑点的行内处理目前只覆盖集团上下文；批次疑点仍走原有批次入口。
- 界面响应：集团控件在每次刷新时会重新读取子疑点清单，密集团 + 大量子疑点时的流畅度未实测。
- 没有操作员工时与全场持续负载实测；先在模型不确定处把交给人工的路径做短，再逐步提高自动处理范围。
