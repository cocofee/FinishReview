# 多圈赛只判最后一圈 + 号码自动对上：方案（第 1–2 步已实施）

状态：第 1 步（lap_wave 纯逻辑）、第 2 步（从赛事元数据读各组目标圈数、左表不列中间圈）已实施；其余待做。

> 2026-10-30 改：目标圈数不再逐条随过线记录发（原 `group_target_laps` 已取消），改为 CycleRace 在赛事元数据的每个组别里发 `target_laps`。不做复核台手动填圈数（用户否决："读取cycle数据即可"）。下文第 2 节中 `group_target_laps` 的描述以本段为准。不改正式成绩；只影响复核台的显示和待办。

## 1. 现状（已核对代码）

- CycleRace 0.50.4（分支 `cocofee/txt`，提交 6a4d456）推送的每条过线记录，已有字段 `lap`：
  - 只有"跑圈模式"（同一赛段有多个计时点，或某组目标圈数 > 1）时才有值，否则为 0。
  - 值 = 该选手在同一计时点上，截至本次的有效过线次数（`pass_index`）。
- CycleRace 内部其实有"组别目标圈数"（`get_max_category_laps`），但**没有随过线记录发给 FinishReview**。
- FinishReview 接收端（`realtime/passage_receiver.py` 的 `PassageEvent`）目前只认 `lap`，没有目标圈数。
- 结论：缺的只有一个数——"这个组要跑几圈"。有了它，就能判断哪一次过线是最后一圈。

## 2. 数据怎么接收

### 2.1 CycleRace 侧（已在 CycleRace 分支 `cocofee/复核台目标圈数` 实施）

现行做法：`src/videopipe_metadata.py` 发送的赛事元数据 `groups[]` 每项增加 `target_laps`，
取值与正式成绩同一口径（`get_category_laps`：本赛段组别圈数 `stage_category.num_laps`，未设时用组别默认圈数，至少 1）。
元数据内容变了 CycleRace 会自动重发。老版本 CycleRace 不发此字段，FinishReview 按 0 处理，所有过线照旧列出。

以下为原方案（已取消）：

在推送的过线记录里增加一个字段：

| 字段 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `group_target_laps` | 整数 | 该组别的目标圈数；0 表示非跑圈组 | 0 |

- 每条过线记录都带上，不另开消息。
- 字段是可选的，`schema_version` 保持 1，老版本 CycleRace 不带这个字段时，FinishReview 按 0 处理，行为和现在一致。
- 目标圈数改动时，记录的 `revision` 会增加，FinishReview 现有的覆盖逻辑会自动更新。

### 2.2 FinishReview 侧（接收）

现行做法：`RaceGroupMetadata.target_laps`（缺省 0，负数拒收）；同一 revision 只多了目标圈数时接受并覆盖
（老复核台存过不带圈数的同一快照，升级后不会因此报冲突）。左表按本赛事、本赛段的元数据取各组圈数；
其他赛事的元数据不用。圈号为 0（未知）的过线一律列出，不当中间圈隐藏。

以下为原方案（已取消）：

1. `PassageEvent` 增加 `group_target_laps: int = 0`。
2. `passage_receiver.py` 解析时用已有的 `_integer_field` 读取，缺省 0，负数拒收（和 `lap` 一样）。
3. 落盘：`cyclerace_passage_events.jsonl` 已经逐条保存完整记录，新字段随之保存，不需要改存储结构。
4. 显示层通过 `_events()` 取事件，无需单独通道。

### 2.3 最后一圈的判定

对同一选手、同一组：

- `group_target_laps = N > 1` 时：
  - `lap == N` 的过线 = **最后一圈，进入现有流程**（分波、点人、导出）。
  - `lap < N` 的过线 = **中间圈，不需要判**，只作参考。
- `group_target_laps` 为 0 或 1：照旧，不分中间圈。
- 选手的最后一次有效过线圈号 < N：**圈数不足**，只提示，不自动判定（可能是未完赛、漏读中间的一圈）。
- 圈号倒退、同一圈重复：沿用现有"圈数异常只提示"的规则。

## 3. 复核台界面

### 3.1 左侧表格

- 新增一列"圈数"，显示 `k/N`（如 `3/3`、`1/3`），和 CycleRace 截图一致。组别只有一圈时整列隐藏。
- 中间圈的行：状态显示 **"中间圈"**，颜色为灰色，默认不显示。
- 表头附近的过滤按钮"只看要处理的"保持不变；中间圈永远不计入"要处理"。
- 增加一个开关 **"显示中间圈"**（默认关），打开后中间圈行出现，只读，点击只看画面，不可判。

示意（默认状态）：

```

│ [只看要处理的 12] [显示中间圈 □]             │

打开"显示中间圈"后，中间圈行显示为灰色：

```

### 3.2 右侧画面提示

选中中间圈行时，提示："第 2/3 圈，中间圈，不判；本组最后一圈看 3/3 那一行。"

选中圈数不足行时，提示："本组目标 3 圈，只看到 2 圈，核对是否未完赛或漏了一圈；不自动判定。"

### 3.3 按键

不新增按键。1、2、3、4 和回车只作用于"最后一圈"行；中间圈行按这些键时给出提示，不改任何记录。

## 4. 对现有逻辑的影响

- `_index_waves`（分波）只取最后一圈的过线，中间圈不参与分波。否则同一选手的 3 圈会被算成 3 次过线，把人数算多。
- 导出（补录、建议删除、建议改号改圈）：中间圈不进入任何导出。圈数不足只出现在提示里，不写进 CSV。
- 集团判定（同一秒内多人）只比较最后一圈，和现在一致。

## 5. 风险与待确认

1. **需要 CycleRace 改一处并发版。** 在它改好之前，FinishReview 无法可靠判最后一圈。不能用"已收到的最大圈号"来猜，比赛刚开始时会错。
2. **计时点是否只有终点线。** `pass_index` 是按计时点数的。如果 FinishReview 收到的不只是终点线的记录，中间计时点会干扰圈数。需要确认推给 FinishReview 的只有终点线计时点。
3. **多组同时比赛。** 每组目标圈数不同，要按组别（`group_id`）取，不能按赛段取。
4. **老数据。** 已经落盘的老记录没有这个字段，按 0 处理，即按现在的方式显示。不回填。
5. **验收。** 合成数据可以测接收和判定；界面要在现场 16 英寸笔记本上看一次，中间圈灰色是否醒目但不干扰。

## 6. 实施顺序（确认后做）

1. FinishReview：`PassageEvent` 增加字段、接收、落盘，测试旧记录（无字段）仍按 0 处理。
2. FinishReview：分圈判定函数（纯函数，可单测）：输入一组过线记录和目标圈数，输出每条的"最后一圈/中间圈/圈数不足/圈数异常"。
3. FinishReview：左表圈数列、中间圈行、"显示中间圈"开关、右侧提示。
4. FinishReview：分波、导出排除中间圈。
5. 给 CycleRace 的字段说明（只描述字段，不改它的代码），由你决定是否交给它那边实施。
6. 合成测试 + 你给一场真实多圈赛数据做隔离验收（需要你提供一场多圈比赛的数据或录像路径）。

## 7. 需要你确认的三件事

- 中间圈默认隐藏、用开关打开，是否合适。
- 第 2 点：推给 FinishReview 的是否只有终点线计时点。

## 8. 号码显示到画面（自动对上）与多圈合并

### 8.1 现在已有什么（已核对代码）

- 全程过线图（`realtime/race_strip.py`）已经在芯片时刻标出号码，并有"是否已确认"的标记。
- 人工点人（`quick_review_panel.add_mark`）记的是压线位置，状态为"已点"。
- **还没有**：把号码标到录像画面里具体某个人身上。

### 8.2 合并后的规则：只对最后一圈的波做自动对上

输入：
- 一波里的芯片，只取最后一圈（`lap == N`；非跑圈组取全部芯片），按芯片时间排序。
- 该波对应过线画面上检测到的人，按穿过压线的先后排序。

**全部满足才自动对上**，否则整波不标，退回现在的手动点：
- a. 检测到的人数 == 最后一圈芯片数；
- b. 录像已校时（有可用的时钟对应）；
- c. 本波没有圈数不足的选手（否则最后一圈芯片不全，人数对不上）；
- d. 相邻两人过线间隔 ≥ 阈值（暂定 0.3 s，需用真实数据定）；过近则顺序可能对错，不自动标；
- e. 本波没有"可能多人"、没有"已点附近"的冲突。

中间圈的画面：**不标号码，不分波**。

### 8.3 三种状态严格分开

项目规则：自动通过不冒称裁判确认。所以：

| 状态 | 来源 | 界面 | 算不算确认 |
|---|---|---|---|
| 自动对上 | 系统按顺序对的 | 画面上虚线框、灰蓝色号码；左表"自动对上" | 不算。只减少点击 |
| 已点 | 操作员点了人 | 实线框、绿色（现有） | 只算"数到人"，不写"已确认" |
| 人工看过整波 | 操作员看完整波按回车 | 波头提示 | 单独记录，不改变每个人的自动/已点属性 |

- 自动对上的号码不写入任何导出 CSV。导出仍只含人工改动（补录、排除、双芯片）。这一点要你确认，我推荐这样。
- 正式成绩仍以 CycleRace 为准，自动对上不改成绩。

### 8.4 界面

画面上（示意）：

```
        ┌──┐        ┌──┐
        │16│ 虚线    │20│ 虚线       （自动对上，灰蓝）
        └──┘        └──┘
      ●  ●  ●  ●   压线上的检测点
```

左表（示意）：

```
│ 顺序 号码 时间          圈数   状态          │
│  5   16  15:50:15.715   3/3   自动对上       │
│  6   20  15:50:15.890   3/3   自动对上       │
│  7   —   15:50:16.300   3/3   可能多人       │
```

波头提示：
- 自动对上时："本波 4 人、4 芯片，已自动对上；看完按回车记为人工看过整波；号码不对的，右键那个人去掉或改号。"
- 不满足时："人数与芯片数不一致，未自动对上，请逐个点。"

按键：
- 整波已自动对上时，回车 = 人工看过整波。
- 4 撤回整波自动对上，退回手动点。
- 右键某个自动对上的人：改号、去掉（沿用现有右键菜单，不新增按键）。

### 8.5 多圈与自动对上合起来的效果

- 多圈组的工作量 = 每组**最后一圈的波数**，不是每一圈都要看。
- 中间圈不出现号码，不占用画面。
- 圈数不足的选手，若最后一圈芯片缺失，人数对不上，整波退回手动，并提示"圈数不足"。

### 8.6 风险

- **检测人数不准**（遮挡、并排、跟车）是主要误标来源。所以只在"人数相等"时标，并要求人工看整波。
- **顺序对错**：两人几乎同时过线时顺序可能错。用 8.2 的 d 条限制。
- **校时误差**：芯片时间与画面的对齐有几十到一百多毫秒的误差，要用真实已校时的数据测，阈值以实测为准。
- **测试数据**：今天的现代五项没校时，且几乎没有芯片，不能用来验收自动对上。需要一场有芯片、已校时、有多圈或单圈的真实比赛做隔离验收。

### 8.7 实施顺序（在第 6 节基础上）

1. 多圈分圈判定（纯函数）。
2. 接收 `group_target_laps`，落盘。
3. 左表圈数列、中间圈隐藏与开关。
4. 分波只用最后一圈（与自动对上共用"最后一圈的波"定义）。
5. 自动对上：判定条件（8.2）→ 画面号码 → 左表状态 → 人工看整波。
6. 导出排除中间圈与自动对上（自动对上不进导出）。
7. 合成测试 → 真实隔离验收。
